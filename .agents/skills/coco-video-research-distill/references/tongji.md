# 同济录课：下载 → 夸克 → 用户导出 → 取回蒸馏

本节记录当前采用的同济录课协作方式，不携带课程内容、账号、缓存或特定自动任务授权。录课来源为 look.tongji.edu.cn；只处理用户有权访问且已选定/授权的课时。

## 职责与默认顺序

| 阶段 | 负责人 | 完成依据/下一动作 |
| --- | --- | --- |
| 发现与选定 | Agent | 列出真实可播放回放，固定 course_id + sub_id，查已有记录 |
| 获取与下载 | Agent | 下载精确课时视频，核对身份、时长、规格、音轨与文件哈希 |
| 上传夸克 | Agent | 在具体材料授权内上传已确认目录，核验终态、名称、字节数、云端文件ID/路径 |
| 生成并导出 | 用户 | 在夸克生成并保存/导出完整文稿；AI总结按需，课件有用时补充 |
| 精确取回 | Agent | 用户告知导出就绪后按课时身份检索下载，核对文稿和材料角色 |
| 蒸馏与入库 | Agent | 文稿全文为主、AI总结导航、课件/视频核画面，笔记及来源登记可核查 |

上传成功后记录 uploaded_waiting_user_summary，并说明等待用户生成/导出，不调用 summary 假装完成逐字稿。用户只说“总结已导出”时检查有没有完整文稿；只有AI总结先标partial，不能称全文已读。

## 工具与调用示例

执行端需已有兼容的 look-tongji-notes/Tongji CLI。先读该版本 Skill 和 help，核对认证与依赖；本仓库不分发该 CLI或其改造版，不保证同名上游含下面所有命令。缺命令时记录工具缺口，不杜撰安装地址或自动用另一ASR替代。

以下命令取自维护端实际可读的 look_tongji.py 参数定义，路径与ID均由执行端提供；TONGJI_CLI 是仓库外工具脚本，材料目录也是仓库外：

```sh
python "$TONGJI_CLI" list-replays --since "$SINCE_DATE" --json
python "$TONGJI_CLI" download-video --course-id "$COURSE_ID" --sub-id "$SUB_ID" --output-dir "$MEDIA_DIR" --workspace-root "$WORKSPACE_ROOT" --no-workspace-prompt
python "$TONGJI_CLI" slide --course-id "$COURSE_ID" --sub-id "$SUB_ID"
```

- list-replays 的当前维护端实现只使用已保存会话，不自动登录；完整枚举与所需详情成功且为空才能说没有回放。分页/认证/网络/详情失败记检查不完整，不能报没有新课。since 下界按命令实际日期语义核对；即使日期有重叠也由课时ID查重。
- download-video 与 slide 不等同于只读发现命令，其当前实现可能进入认证回退。没有登录授权时不运行会触发回退的命令；先核实执行端行为，不能凭 --no-workspace-prompt 认定禁止登录。没有当前版本支持的 no-login 参数就不要编造。
- 下载不用 transcribe/trans/batch-transcribe 代替；默认同济正文来自夸克用户导出，不自动调用BcutASR或本地转写。额外转写须具体授权。
- 没有独立画质参数时不编造 --quality 1080p。优先取得平台实际可用高清源，记录ffprobe实际规格；工具只选到低清时说明限制，按授权的正常来源网页核对可选清晰度。不假定一定有1080P，也不把上采样当高清。
- slide 可选，不要求教师提供课件才能开始；取不到课件时对需要视觉证据的结论回查视频画面，读不清就保留缺口。不按时长必须超过一小时判课程完整，实际课时可能更短。

## 查重、命名与取回

course_id + sub_id 是完整主键，课程名/上课日期仅辅助，动态 collection_id 由目标知识库登记。录课上传名保留两段ID，例如 <course_id>_<sub_id>.mp4；导出材料沿用同前缀，并分别登记文稿、AI总结、课件。对缺ID的导出先核对课程、教师、日期、时长和原任务，不能靠同名并入。

夸克操作复用 [quark.md](quark.md)。精确查询关键词为完整的 <course_id>_<sub_id>，不只查课程名或“总结”；使用当前官方 search help 的真实参数，不自行扩展搜索。读取完整Artifact筛选匹配材料，再按 download实际说明取回。没有找到则保留waiting状态，不重下录课或重传。

同一课时有既有视频/上传回执就从该状态继续；只有媒体丢失或版本/来源实际变化才考虑重新获取，并保留原因。文稿更新时只修订相关笔记，原文原格式与哈希不改写。保存绝对路径由目标知识库选择，分发仓库只用环境变量和占位符。

## 按仓颉方法蒸馏

普通课程笔记采用 [distillation.md](distillation.md) 的方法，接入仓颉的三个层次：

1. 全文理解：分块读完文稿，建立课程结构、关键术语、推导关系、教师例子和待理解问题；AI总结只作导航，不代替正文。
2. 方法提取：按当前学习目标提取概念、计算/证明步骤、前提、案例与反例；教师内容优先，补充解释与自编例子明确标注。不要把每个定义硬写成“操作技能”。
3. 核验：来源足以支撑结论、方法能在合法输入上执行、能帮助当前任务；缺来源/条件/画面时列待核验，不编造教师步骤。每项关键结论保留时间码、文稿段落/行号或课件位置。

普通“蒸馏”交付课程笔记和证据回链，不自动创建能力包。用户明确说将指定材料做成可调用Skill时，先读取执行端 cangjie-skill，按当前版本阶段0—5、验证与编译要求执行；缺该技能先记录依赖，不能假装已完成仓颉流水线。用户指定执行方式优先，不为普通笔记固定五代理。

## 授权、等待与清理

本节写明方法不等于授权服务器访问全部课、上传全部课程或运行每日自动任务。普通任务用具体课时授权或用户明确的范围授权；本机既有自动任务权限不随仓库传递。账号与录课材料私密，仓库只保存技能，禁止把私有课件/笔记/令牌当作本次文档推送。

暂停在等待导出时保留云端ID和下一动作；续跑先查导出，不重传。一般任务核验云端保存后提醒临时视频准确路径，不自动删除。任何自动清理必须另有执行端明确授权、精确文件范围和回执，不能继承作者机器的例外。
