# 远端配置与实际能力

## 必要配置

1. 克隆分发仓库，按 README 建虚拟环境安装 requirements；运行 doctor。它只证明命令存在及版本，不检查登录、MCP 或下载。
2. 在目标知识库安装技能，读该库规则。设仓库外材料根、临时媒体根、笔记落点与来源总账；复用原有目录。所有路径由目标环境配置，不依赖作者机器。
3. Python 3.10+；bili 和 yt-dlp 由 requirements 固定基线；视频合并/音频抽取/画面抽取需要 ffmpeg 和 ffprobe；YouTube JS 支持按 yt-dlp 官方 EJS 说明检查 Node 与依赖。工具版本变化后更新验证记录，不能自动升级后宣称原测试仍有效。
4. 逐项记录 installed / connected / authenticated / tested，而非一个“可用”布尔值。凭据留仓库外，日志不记录令牌、Cookie、签名 URL。GitHub 认证不等于平台认证。

## 可选能力怎样接入

| 能力 | 配置与验收 | 不具备时 |
| --- | --- | --- |
| Bili23 MCP | 依据[官方文档](https://bili23.scott-sloan.cn/doc/mcp-server.html)在运行该软件的主机启用服务；默认本机 http://127.0.0.1:23330/mcp。访问令牌放执行端秘密配置，按 Codex 当前 MCP 配置方式连接并读取实际 schema，解析公开视频和查询任务分别验收。程序需运行，但不要求前台窗口；不随仓库安装 GUI | 服务器媒体用 yt-dlp 一次替代；不要求为了取字幕部署桌面 GUI |
| 远端连本地 MCP | 必须有用户授权及可达主机，可用 SSH 隧道仅转发本机监听服务；远端 127.0.0.1 不会自动连作者电脑。不公开端口，不把令牌写仓库 | 标 unavailable，采用服务器路线 |
| Chrome/内置浏览器 | 执行端真实暴露浏览器工具并能打开目标来源页面；已有会话优先。Chrome 插件字幕接口只在实际暴露时使用 | CLI 没浏览器时明确缺口，不声称安装 Chrome 就具备 Agent 控制接口 |
| 转写 | 已安装引擎、模型/硬件、输出格式和时间码能力；只读核对后对授权媒体运行 | 按具体授权采用夸克，或请求最少补充 |
| 夸克 | 安装官方 Skill、CLI，按官方要求绑定当前执行端；读 quark 参考 | 不阻塞已有全文蒸馏；缺正文则记录待补 |
| 同济录课CLI | 执行端提供兼容工具，核实list-replays/download-video/slide实际help、会话与认证行为，读tongji参考 | 可处理用户提供的完整文稿；不能宣称远端已能下载录课 |
| cangjie-skill | 普通蒸馏方法在本仓库可读；完整Skill化须执行端已安装该技能并读其当前入口 | 普通笔记不受影响；完整Skill化记录依赖缺口 |

依赖列表中的可选能力不要求全部安装。远端第一次只配置真正需要的路线；安装、模型下载、登录、外部上传的授权与成本分别判断，用户已覆盖则不重复问。

## 复用登录，减少人工

用户已允许复用时，可经 SSH/秘密管理单独传送与当前工具兼容的凭据到仓库外；最小文件、仅当前用户读写。不复制整个浏览器 profile，不把凭据放 Git，即使私有也不放。

- bili 同版本凭据格式见 platforms；YouTube yt-dlp 用 Netscape Cookie 文件，acquire.py 的 --cookies-file 显式读取。Cookie 过期或跨网络失效要如实报告。
- 夸克官方 OAuth/绑定状态与 B站、Google Cookie 无关。不承诺复制本地夸克配置即可在服务器登录；按当前官方 auth 文档判断复用支持，否则一次绑定。没有用户授权不主动启动登录。
- 令牌失效可以在已有授权内刷新；实际登录变化后仅重试原失败目标一次，保留旧回执。不要让用户对每个视频重新登录。

私有仓库可以保存非敏感的能力报告和参数模板；配置实值、登录记录、云端文件 ID/材料回执默认由目标知识库按权限保存。
